# Technical Design

## 目标

本项目的目标不是先识别某个具体动作名称，而是先建立一个可复用的“重复检测”领域内核。

底层系统不直接理解“张开”“握拳”“深蹲”“俯卧撑”这些语义名称。它处理的是姿态向量流，以及姿态向量在时间上的变化。动作名称属于后续解释层，不应该成为重复计数的前置条件。

当前 Web 手势计数只是验证场景，用来低成本验证重复定义、关键帧提取、姿态向量相似度和闭环计数逻辑。它不是最终业务场景。

## 核心定义

### 姿态向量

`PoseVector` 是每一帧姿态的归一化特征表达。

对于手势场景，它来自手部关键点。对于身体姿态场景，它来自人体骨架关键点。二者在重复内核看来没有本质区别，都是向量空间里的点。

姿态向量进入领域内核前必须完成归一化，包括：

- 平移归一化
- 尺度归一化
- 关键点置信度过滤
- 必要的平滑处理
- 低质量帧剔除或降权

### 关键帧

`Keyframe` 是姿态轨迹中的代表性稳定点。

它不应该由动作名称决定，而应该由运动状态决定。通常满足：

- 短时间窗口内姿态变化速度下降
- 变化率接近 0
- 运动方向发生反转，或进入局部稳定状态
- 关键点置信度足够高

工程上不能只依赖单帧导数，因为视频输入有噪声。关键帧检测应该基于短窗口趋势、速度下降和回弹确认。

### 重复

一次 `Repetition` 定义为：

```text
K_A -> K_B -> K_A'
```

其中：

- `K_A` 是起点关键帧向量
- `K_B` 是明显离开起点后的反向关键帧向量
- `K_A'` 是返回关键帧向量
- `K_A'` 与 `K_A` 足够相似
- `K_A -> K_B` 和 `K_B -> K_A'` 的偏离幅度足够大
- 周期时长在合理范围内

关键点是：重复不是“相似关键帧多次出现”，而是“离开后再次出现相似关键帧”。

这可以避免把静止保持某个姿势误判为重复。

## 当前手势验证场景

当前实现使用浏览器摄像头和 MediaPipe 手势模型获取手部关键点。

MediaPipe 输出的 `Open_Palm`、`Closed_Fist` 等手势标签只用于调试展示，不是重复计数的底层依据。

当前计数的主要依据是：

- 从手部关键点构造连续运动信号
- 根据运动信号检测关键帧
- 从关键帧提取手部姿态向量
- 用关键帧向量余弦相似度确认是否回到起点
- 满足闭环、幅度、时间和冷却条件后计数

当前版本仍带有手势开合验证的痕迹：关键帧候选主要来自一维开合信号。后续通用化时，应将关键帧候选改为由姿态向量变化率和多维运动主轴产生。

## 插件化方向

系统应拆成稳定的重复内核和可替换的姿态插件。

### 重复内核

重复内核只处理领域概念：

- 姿态向量流
- 运动速度
- 关键帧
- 姿态簇或原型
- 离开与返回
- 闭环判断
- 次数、边界、置信度和节奏

重复内核不关心输入来自手、身体、器械还是其他传感器。

### 手势插件

手势插件负责：

- 从手部关键点生成归一化姿态向量
- 提供手势相关的运动信号或运动主轴
- 评估手部关键点质量
- 输出可供重复内核使用的 `PoseVector` 和候选关键帧信息

手势插件的当前作用是验证重复定义，不是产品最终目标。

### 身体姿态插件

身体姿态插件负责：

- 从人体骨架生成归一化身体姿态向量
- 提供关节角、重心高度、肢体距离或多维主运动轴
- 处理身体遮挡、机位变化和关键点置信度
- 输出可供重复内核使用的身体姿态向量和候选关键帧

健身、康复、日常行为记录等场景应通过身体姿态插件或其派生插件扩展，而不是修改重复内核定义。

## DDD 实现原则

后续代码实现采用 DDD 的概念组织领域逻辑。

建议的边界如下：

- `Repetition Core`：重复检测领域内核，包含关键帧、闭环、相似度、周期、置信度等规则。
- `Pose Plugin`：手势、身体姿态等输入插件，将不同感知数据转换为统一领域输入。
- `Infrastructure`：摄像头、MediaPipe、模型文件、浏览器 API、资源加载。
- `Application`：连接插件和重复内核，维护实时会话状态。
- `Presentation`：UI 展示、调试面板、日志和用户交互。

领域规则应尽量留在 `Repetition Core`，不要散落在 UI 或 MediaPipe 适配层中。

## 类型编程原则

后续实现应迁移到 TypeScript，并用类型表达领域约束，减少业务语义被普通 number/string 混淆。

建议使用类型来区分：

- `TimestampMs`
- `NormalizedPoseVector`
- `MotionSpeed`
- `SimilarityScore`
- `ConfidenceScore`
- `Keyframe`
- `CandidateKeyframe`
- `ConfirmedKeyframe`
- `PosePrototype`
- `RepetitionCycle`

关键原则：

- 原始关键点不能直接进入重复内核，必须先转换为归一化姿态向量。
- 未确认关键帧不能直接参与计数。
- 相似度、置信度、时间戳等值应使用明确类型，避免单位和语义混用。
- `A -> B -> A'` 应表达为领域状态流，而不是零散布尔变量。
- 插件输出应遵循统一契约，重复内核不依赖插件内部实现。

类型系统不能替代运行时校验，但可以让业务表达更接近领域语言，并减少错误组合进入核心规则。

## 演进路线

1. 保留当前手势验证场景，继续验证关键帧闭环逻辑。
2. 将重复内核从 UI 脚本中拆出，形成独立领域模块。
3. 引入 TypeScript，用领域类型表达 `PoseVector`、`Keyframe`、`RepetitionCycle` 等概念。
4. 将当前开合信号提取封装为手势插件。
5. 增加基于姿态向量变化率的通用关键帧候选。
6. 增加身体姿态插件，复用同一个重复内核。
7. 在重复结果稳定后，再引入动作命名、动作质量评估和场景记录。
